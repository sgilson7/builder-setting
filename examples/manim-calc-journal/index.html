The plan: one core works the method, the page and Manim both draw it

Eight decisions in build order, in PLAN.md. The calculator's keys and the written methods live in the core; the page keeps one SVG element per glyph and moves it where each step puts it; a small export binary writes the same steps for four examples, and Manim replays them. Step through one press of = below. The scene is proposed: nothing is built yet.

One press of = , from the key to the moving digits. Proposed.

Every step as text
  1. 478 + 356 =. The page sends the key; the core works the sum and its method; the page moves each digit to where the core puts it.
    1. The = key (or Enter, looked up in the core's key list) calls act with the state and "key.equals".
    2. The shim passes the strings to the core unchanged.
    3. calc::press works 478 + 356 = 834 in integers and keeps the sum as the last work.
    4. method::steps lays out the column addition: digits, the ones and tens carries, the answer, each with a pixel position from data/stage.json.
    5. api::ui puts the display, the keys and the current step's glyphs and sentence into the screen.
    6. The screen goes back through the shim as JSON.
    7. The stage moves each glyph to its new position with a CSS transition; Next and Play ask the core for the next step the same way.

How I read Builder, and how I will build Manim Calc

What Builder asks of me

Builder's rules are the same for every project, so they come written; each names the card that holds it (python3 tools/ask.py --card ID). I hold to all of them. What follows this list is particular to this project.

  • Every application rule lives in the core, which does no input or output; the shim only translates; the page only draws what the core returns (card:spec.R1, card:spec.R2, card:spec.R5, card:spec.R6).
  • Nine stages: the description, the approval of the plan and every deploy are yours; I stop where they need you (card:docs.procedure, card:spec.R9, card:claude.r9).
  • Each new behaviour test is shown to fail with its behaviour broken, and ./scripts/check.sh passes before a handoff (card:claude.r6, card:spec.R8, card:claude.r10).
  • SECOND-ORDER.md records what I decide alone, as I decide it; later requests become TRIAGE.md rows (card:claude.r7, card:docs.procedure.numbered-requests-and-experiments).
  • Words follow GLOSSARY.md and TONE.md (card:claude.r11, card:claude.r12).
  • This journal gets an entry for every decision, visible change, divergence and deploy, and questions come as answer chips (card:claude.r15, card:claude.r16).
  • One agent, and the quick check while iterating (card:claude.r17, card:claude.r18).
  • Builder is read through cards, STATE.md is rewritten at each milestone, and long output goes through quiet.sh (card:claude.r19, card:claude.r21, card:claude.r22).

One item fits less well than it reads. The first stop, for the plan, does not happen: the brief approves the plan in advance and nobody will answer during this run, so I build on every question's default below and say so in an agreed entry (card:docs.journal.the-opening-entry, card:spec.D20).

What this project adds or changes

The description asks for two things that pull apart. A calculator is interactive: the reader types the numbers. Manim renders video ahead of time, in Python, on a machine with Cairo, Pango and FFmpeg; the page cannot run it (card:kits.manim.when-to-use-it-and-when-not). My reading, CM-Q1 A, keeps one source for both:

  • The core works out the method. For each operation the core produces the steps of the written method (carries, borrows, partial products, long division), each step a list of glyphs with integer positions and a sentence. The core does all the arithmetic in integers, so D2 (no floats) holds without change.
  • The page animates those steps live on the reader's numbers. It sets each glyph's position from the step and lets a CSS transition move it there, the way Manim's Transform moves an object. The page computes nothing, so D3 holds: every position, size and duration comes from the core or from data/stage.json (card:spec.D3).
  • Manim renders the same steps. I copy kits/manim/ (card:kits.readme.the-kits, card:kits.manim.what-to-copy.p2) and write one Manim code scene that replays a step file the core wrote, for one worked example per operation. No Python recomputes a digit (card:spec.R1). The kit's player shows the four renders beside the calculator, with a still per step under reduced motion.

The kit changes no reference default. I leave out its site pages (sitepages.py, publish.py, the deck and its tests), because there is no site of animations here and nothing is published. Its setup-manim.sh calls brew --prefix; this run may not run Homebrew, so my copy takes BREW_PREFIX instead (R1.2). No row goes in the change table.

CM-Q1 What should "interactive Manim animations" mean on a static page?

Manim renders video ahead of time, on a machine with Python; a page in a browser cannot run it. So an animation of the numbers a reader types has to be drawn by the page, and a Manim render can only show numbers chosen in advance. blocks: the whole build: the core's scene output, the page's stage, and whether kits/manim is copied

CM-Q2 Which numbers does the calculator take?

Written methods are taught on whole numbers first. Decimals change every layout (the point has to line up) and roughly double the work. blocks: the core's number type, the display, and every method's layout

Countries lay these out differently; the layout is a teaching decision and stays yours. blocks: the core's step rules for each operation

2026-11-23ready for you

Ready for you: open it and work one sum by hand beside it

How to open it

In manim-calc/: ./scripts/build.sh, then python3 scripts/serve.py, and open the address it prints. Opened from disk the calculator still runs, but the four Manim renders cannot load their files.

What to try first

  • Type 503 − 278 = and press Pause, then Next: check the borrow across the zero against your own working (5 → 4, 0 → 10 → 9, 3 → 13; answer 225).
  • Type 952 ÷ 5 = on the keyboard (/ and Enter): the display shows 190 r 2, the last step names the remainder.
  • Type 3 − 5 =, then × 4 =: −2, then −8, each with its minus-sign step.
  • Play one of the Manim renders below the calculator, in Safari if you can (R1.17).

Rough edges

  • The layouts and wording of the four methods are one common version; yours may differ (R1.16, CM-Q3).
  • Long division of a long dividend makes a tall stage.
  • The light and dark Manim renders are the same picture, so the media is twice what it needs to be (R1.13).
  • The browser check never plays a Manim clip (R1.17).

Checks

86 cargo tests and 29 kit tests pass; 24 of 24 breaks caught; ./scripts/check.sh's result is quoted in HANDOFF.md under "What passed". Nothing is deployed.
